## Release gates (all unchecked)

Tick a box only with attached evidence. Do not mark unperformed work done.

### 1. Version, signing, and approval

- [ ] Final version, tag, and source commit fixed. Release marker pinned for this build.
- [ ] `APEXSHOT_STUDIO_VERIFY_KEY` and `APEXSHOT_STUDIO_RELEASE_TIMESTAMP` readable at repository or organization level and accepted by the tag workflow.
- [ ] Public verify key matches the backend-only signer, checked by fingerprint rather than by printing values.
- [ ] Production `STUDIO_SIGNING_KEY` provisioned only in the backend secret store. Absent from source, desktop packages, logs, and desktop GitHub Actions variables. Sandbox tests use a separate non-production key.
- [ ] `stable-release` environment exists with required reviewers.
- [ ] If publishing to AUR: `AUR_SSH_PRIVATE_KEY` and a pinned `AUR_SSH_KNOWN_HOSTS` entry configured and verified. No `ssh-keyscan`.

### 2. Cloud and Studio sandbox (needs separate approval)

- [ ] Sandbox Studio product created. Its ID configured in the sandbox backend only.
- [ ] Hosted sandbox checkout with a test card completes, and the signed webhook is delivered.
- [ ] Repeated webhook delivery creates one purchase, one license, and one confirmation.
- [ ] One license recovered through the authenticated account.
- [ ] Full and partial refunds follow the documented rules. A duplicate replay changes nothing.
- [ ] Refund behavior is honest: server recovery stops after a full reversal, but an already activated offline token cannot be remotely revoked.
- [ ] Cloud and Studio stay separate: Cloud cancellation does not revoke Studio, and a Studio refund does not change the Cloud tier.
- [ ] Annual Cloud product stays off unless it is separately gated and tested.

### 3. Desktop paid paths (configured candidate, native and Flatpak)

Run these checks for each package being shipped. An unshipped Flatpak is not a dependency of the native release.

- [ ] With a valid token: Motion MP4 export, non-identity static presentation transform, and advanced zoom output succeed.
- [ ] Save, copy, and upload paths apply the gate when they actually use a Studio capability; inactive or unused settings do not block free output.
- [ ] Free outputs unaffected: normal image backgrounds, clean exports, legacy zoom, and classic animation.
- [ ] Without a valid token: paid outputs show the Studio card and do not export. Free outputs continue.
- [ ] Restart and offline: an activated token still validates.
- [ ] A malformed or invalid replacement is rejected, and the previous valid token is kept.
- [ ] Covered and uncovered update-marker builds behave as documented.

### 4. Candidate package and regression

- [ ] Capture, source, cancel, scaling, clipboard, and save checked on each supported desktop.
- [ ] Recording, audio, pause, and resume checked on each supported desktop. Fedora recording stays unsupported and must refuse with a notice.
- [ ] Project reopen and export playback checked.
